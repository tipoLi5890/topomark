## Maintenance

```bash
topomark owner <path>     # which area owns this file, its fan-in and review state
topomark draft <area>     # rows missing from an area's file table, summary and fan-in prefilled
topomark gen              # regenerate _generated/ after the code structure changed
topomark sync             # rewrite the fan-in numbers written in area files
topomark check            # coverage, dead paths, ownership, line caps, fan-in, generated files, stamps
topomark stale            # rows to review (blocking) and body-only changes (advisory)
topomark diff <path>      # what changed in a unit since its review: interface first
topomark stamp <path>     # you reviewed the row and it is still true: record that
```

**Staleness is caught by per-unit review stamps ([stamps.json](stamps.json), written by
`topomark stamp`), not by timestamps:**

- Each unit records the SHA-256 of its *surface* (header comment plus public signatures, constant
  values, enum members) and the git blob of its content at the moment its row was reviewed.
- The surface changed (new or changed signature, constant, header) → `topomark check` fails until
  someone reviews that row and stamps it. Only a body changed → `check` stays green and
  `topomark stale` lists it as advisory.
- Each area also stamps its cross-area callers. A new caller from another area means the data flow
  and cross-area sections need a look, then `topomark stamp --edges <area>`.
- Editing an area file never blesses other rows. New units have no stamp and removed units leave an
  orphan stamp; `check` reports both.
- A stamp is a statement that someone read the row. Never stamp a whole area to make `check` green:
  `diff` first, update the row, then stamp.
- Optional commit gate: `topomark hook install` (it keeps an existing pre-commit hook).

When you add, move or delete a file, or its responsibility changes: update its area's file table,
then `topomark gen`, `topomark sync`, `topomark stamp <path>`, `topomark check`. Ownership comes from
each area file's `scope` frontmatter (longest prefix wins); a new directory needs a scope entry in
some area or `check` reports it as unowned. Fan-in is approximate: it says how careful to be, the
area file says what to update.
