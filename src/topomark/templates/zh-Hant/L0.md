## 維護

```bash
topomark owner <path>     # 這個檔歸哪一區、扇入多少、審閱狀態
topomark draft <area>     # 區檔檔案表缺的列，摘要與扇入先填好
topomark gen              # 程式結構變了：重產 _generated/
topomark sync             # 把區檔裡的扇入數字改成最新
topomark check            # 覆蓋率、死路徑、歸屬、行數、扇入數字、產生檔、審閱戳記
topomark stale            # 需審的列（擋關）加上只改內容的檔（提示）
topomark diff <path>      # 這個單元從上次審閱到現在改了什麼，先列介面
topomark stamp <path>     # 審過那一列、摘要仍正確：蓋章
```

**過舊偵測靠逐單元的審閱戳記（[stamps.json](stamps.json)，由 `topomark stamp` 寫入），不靠時間戳記：**

- 每個單元記一個**介面雜湊**（SHA-256，只算檔頭註解與公開簽章、常數值、enum 成員）和審閱當時內容的 git blob。
- 介面變了（新增或修改簽章、常數、檔頭職責說明）時 `topomark check` 會失敗，直到有人審過那一列再蓋章；
  只改函式內容不擋，`topomark stale` 會提示。
- 每區另有**跨區呼叫端雜湊**；出現新的跨區呼叫端時，要審「資料流」與「跨區依賴」兩節，再
  `topomark stamp --edges <area>`。
- 修改區檔本身（例如修錯字）不會替別的列放行；新檔沒有戳記、刪掉的檔留下孤兒戳記，`check` 都會擋。
- 蓋章是「我看過了」的聲明。不要為了讓 `check` 變綠而整區蓋章：先 `diff`，改那一列，再蓋。
- commit 前自動檢查（選用）：`topomark hook install`，原有的 pre-commit hook 會保留。

新增、搬移、刪除檔案，或檔案的職責變了：改那一區的檔案表，再跑 `topomark gen`、`topomark sync`、
`topomark stamp <path>`、`topomark check`。歸屬由每個區檔 frontmatter 的 `scope` 決定，最長前綴勝出；
新開的目錄要掛到某一區的 scope，否則 `check` 會說沒有任何區涵蓋它。扇入是近似值：數字只說要多小心，
該動什麼看區檔的那一句話。
